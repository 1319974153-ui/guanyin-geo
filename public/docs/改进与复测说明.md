# 改进事项与复测闭环

在「告警与改进待办」点击事项的「发起复测」，系统根据原诊断的问题编号、或告警关联回答的问题编号，选中当前品牌的问题。产品范围明确的诊断只允许选择该产品的问题；手动事项没有关联问题时需要选择实际题目。

复测表单自动填入事项名称、当前问题版本和已配置的模型。提交前可检查模型、问题和请求次数，每轮最多 80 次，受工作区任务及模型调用配额约束。点击「创建并入队」后，已启用的本机执行器可能自动调用模型并产生供应商费用；「创建并开始执行」由当前页面立即派发。

目前这条自动链路执行单次模型 API 采样，不联网，不代替豆包、元宝等网页 / App 消费端实测。消费端同题实测仍需独立接入与验证。来源诊断若来自消费端，得到 API 回答也不构成该消费端问题已修复的证据。

## 自动保存的内容

- 任务保存当前问题正文、版本、产品归属、模型和重复次数，关联原待办。
- 创建任务和更新待办在同一数据库事务内完成；过期页面提交被拒绝，响应丢失后重试同一请求不会重复创建任务。
- 每个事项同时只允许一批未结束的关联复测。失败或结果不确定的任务，需要到任务记录核对、恢复或取消，不能绕过它再建一批默认重试。
- 每条回答返回后先保留模型回执，再保存业务结果。全部请求成功结束且实际回答齐备时，自动把一份任务证据附回原事项，并将状态改为「待复核」。这不表示效果改善，也不会自动标成「已复核」。
- 任务结果页显示原事项入口，原事项显示全部关联任务和原始回答入口。

## 无法自动关联时

失败、结果不确定、已取消、实际回答缺失、问题版本或产品归属变化，都不会作为完整复测自动关联。待办保留「待复测」；可查看任务记录，并点击「重新关联已完成结果」获得具体原因。

待办最多关联 5 条证据，历史最多 100 条。达到上限时不会覆盖已有证据；先移除不再需要的关联或新建后续事项。后台每次最多检查 200 个待复测事项，手动关联可以指定单个事项。

复核时服务端重新检查任务归属、回答完整性和当前问题版本。只有所有者、管理员或审核人能标记「已复核」；编辑可创建任务和登记处理结果，查看者不能执行。重新打开已复核事项需要管理员。

## 恢复与费用

恢复业务备份后，未完成任务暂停，未知计费结果不自动重发。已取得的模型回执可以恢复到业务资料，再关联原事项，无需再次生成。执行器离线时不推进；恢复联网后继续到期任务和结果关联。

## API 参数

已有 `POST /api/v1/tasks` 在单次 `sample` 请求中可增加 `actionId` 与 `actionRevision`，分别是当前授权品牌的改进待办编号与最新版本。应用 Key 仍需同时具备 `write` 与 `run`。其余问题、模型、次数字段与普通任务相同。

相同请求 `id` 的重复提交返回原任务。关联复测的参数发生变化时应使用新的逻辑请求；服务端拒绝把同一请求 ID 改用于不同问题或事项。`GET /api/v1/tasks/items?planId=…` 返回任务概要、关联事项以及各条原始回执。

网页登录后的 `POST /api/operations/retests/collect` 接受 `{brandId, id}`，`id` 为指定待办；省略则检查此品牌的待复测事项。该管理操作不开放给应用 Key。任务执行器会自动进行同样的结果关联，无需反复点击。

## 验收范围

已通过本地真实数据库事务、持久化队列和受控模型返回的 14 组功能测试，包括并发/幂等、回滚、权限、版本变化、恢复不重复计费、结果归属及前端丢失响应恢复。生产功能已发布不代表真实客户模型质量或消费端效果已验收；实际账号操作仍需可用的正式登录会话。

## 问题机会与批量建立（0.27）

“品牌与竞品 → 优先处理”根据当前版本样本、标签核对、有效资料和稿件状态安排工作。每条可生成并分配待办，或为当前显示类型的前 50 条批量建立；默认分配给工作区所有者。批量由服务端重新计算依据，来源信息由服务端生成，页面不能自行提交一个虚构优先项。变动过的依据需刷新后重新选择。

同一品牌、窗口、平台/入口/模式/数据类型及完全相同依据下复用原自动事项，不会重复新增，也不会重新打开已经复核的事项。新依据或新窗口可形成后续事项。一次提交最多 50 条；每个品牌最多 1000 个待办和 1000 个机会批次，容量不足整批不写入。请求丢失后保留请求编号和原选择重试；已保存回执优先恢复，后续题库改变不改写旧回执。

机会来源保留当时的问题、版本、产品、原因、分母和回答/稿件编号。其关联复测只能选择原问题和原产品归属。题库产品发生调整后需重新评估机会；单纯问题文字改版仍用当前版本采样，不能把它自动解释为同版本效果对比。清单的规则版本与方法随报告固定保存。
