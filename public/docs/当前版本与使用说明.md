# 观引 GEO 0.46.0 · 当前版本与使用说明

本版本是带持久化存储的真实工作台，首次进入没有示例品牌或虚构指标。当前访问范围保持私有，使用托管平台登录；每个登录身份拥有隔离的工作区，并可按验证邮箱加入获授权的团队工作区。

## 本次更新

- 参照 Answerbit 的任务组织方式，重排监测、证据、内容与交付导航。品牌概览展示真实指标、平台趋势和下一步行动。
- 新增回答记录页：关键词与名称匹配筛选、分页、原回答和引用阅读；链接保留当前统计范围。
- 趋势支持折线 / 热力视图及指标切换，无样本保持空值。内容管理增加可搜索列表，保留原看板。
- 本次没有新增消费端自动采样，不恢复此前停止的检测。


- 单篇和批量写作统一使用登记名称、官网和有效事实版本；都可设置风格与写作简报。
- 草稿保存生成时的身份、简报和资料快照时间，在编辑面板展开查看。模型应区分建议示例与实测，输出仍需审核。详见 [内容写作依据说明](内容写作依据说明.md)。

- 发布记录可分别保存账号、平台阶段、回执地址和状态说明。草稿、审核中、审核未通过、人工登记已发布与下线不再混为一个状态。
- 平台显示已发布但暂时没有公开链接时，可以保存真实回执；后续取得公开文章 URL 再启用复测。创作后台和编辑器地址不作为公开文章抓取。
- 抖音、小红书、百家号、搜狐号增加渠道入口自动填入和域名识别。当前仍是发布记录和入口辅助，社交平台自动外发适配器尚未接入。
- 更换发布阶段时，旧网页检查会标为历史结果；进行中的检查不会套用到新的阶段。机会待办也按实际发布阶段判断下一步。

## 从第一份资料开始

1. 创建品牌：填写名称，选择行业，官网可选。
2. 粘贴产品资料或读取 TXT / Markdown。创建品牌后，可在品牌知识库上传 PDF / DOCX / PNG / JPEG，自动抽取文字或识别扫描件，保存原件、全文与选中的摘录。原生文字自动核对出处，OCR 摘录需对照原件确认。
3. 编辑行业模板提供的问题，保存第一组监测问题。
4. 自动比对一致的资料直接确认，缺少原文或无法匹配的项目进入待处理列表。只有有效且已确认的资料用于写作。
5. 从具体问题创建模板草稿；如已配置模型，也可以点击 AI 写作。核对稿件后送审、通过，再创建发布任务。
6. 选择渠道自动填入入口，核对发布账号。在渠道操作后保存平台阶段、回执和说明；取得公开文章 URL 后可识别标题并复测。人工登记的“平台已发布”仍需对应回执，不代表搜索收录或 AI 引用。
7. 从平台手动保存回答全文与实际引用，导入工作区复盘。模型 API 测试单独保存，不能替代消费者在网页/App 中看到的结果。
8. 查看报告、导出 Markdown 与原始回答；使用浏览器打印另存 PDF。

## 模型使用

在“设置与完整功能 → 服务连接”选择供应商，填写自己账号实际可用的模型名称/接入点 ID 和 API Key。保存不等于调用成功，首次操作会返回实际结果或明确错误。当前适配器不联网，API 回答没有引用字段时不会编造引用，未标注推荐时推荐率显示空值。

固定模板无需模型密钥。网页静态检查不需要模型密钥。模型费用由客户的供应商账号承担，当前日限额是调用次数上限而非金额预算。

## 数据与恢复

不要把第三方密钥放进品牌资料或正文。配置页单独处理密钥，导出的业务工作区不包含模型密钥。

浏览器刷新后从服务端重新载入。若另一页面已经更新，服务端拒绝覆盖新版本；先导出待恢复修改，再重新载入进行合并。完整业务备份、同工作区离线导入和团队品牌授权已实现；正式业务恢复、多成员实账号、商业化承载和完整安全评审仍需独立验收。

## RunningHub 连接（0.3.1）

已支持 RunningHub 文本网关。当前站点所有者可直接使用服务端托管的 `qwen/qwen3.8-max` 配置，密钥不进入前端或业务导出，也不会提供给其他登录身份。沿用同一账号的 RunningHub 按量额度；并非免费调用。

“服务连接 → 验证连接”只发送一次简短测试，输出上限 32 token，保存请求 ID 和用量，不创建品牌或 GEO 样本。验证成功才显示实测时间；失败不会自动重试。AI 写作仍只使用已确认资料，API 测试不注入品牌资料、不主动启用联网检索。日限额包含验证、写作、重新拟标题和测试的合计请求数。

## 自动填写与出处核对（0.4）

- 创建模板内容时根据问题与风格填好标题；修改风格时联动更新，手工修改后保留你的标题。AI 写作默认随正文拟题；编辑页可重新拟标题，已配置模型时使用模型并计入用量。
- 发布记录关联文章后自动带入标题。知乎、今日头条、微信公众号、B站自动提供平台入口；官网使用品牌官网。行业媒体及其他渠道可自定义入口，保存后在当前品牌下复用。
- 平台入口不作为文章 URL。没有发布适配器时，真实文章链接仍需发布后粘贴；读取成功后自动补全标题与渠道，遇到登录或访问验证保留原值并说明原因。不会因保存平台入口而标记文章已发布。
- 新导入 TXT/Markdown 或粘贴文字会保存原文并自动核对。已有资料可点击“自动核对全部出处”，每批 12 条，处理进度与结果可见。来源是 URL 时读取公开网页正文；来源是文件时比对保存的原文。
- 自动通过表示完整摘录与原文一致，不代表独立核实所有业务结论。找不到原文、正文不一致、来源不可访问或过短的片段留待处理，不直接标为通过。
- 旧版本只存文件名而没有原文的记录，需要补传一次同名原文，随后可以批量核对。原文跨品牌隔离；每条自动核对保留时间、出处、原文指纹及匹配摘录。
- 修改事实或出处会清除旧的自动核对结果，重新进入待确认。核对期间被修改的资料不会被旧结果覆盖。

## 0.5 平台基础

- 团队页可按登录邮箱授权管理员、编辑、审核人和只读成员；编辑/审核/只读按品牌过滤。撤销权限下一次请求生效。
- 成员还需先有本网站访问权。本产品没有自动发送邮件或更改站点访问范围，线上多成员登录验收尚待真实成员。
- 编辑能修改草稿，不能把改稿直接标记为已审核；审核人能审核已有内容，不能同时替换原稿和事实证据。
- 所有者可调整容量和每日模型调用配额；默认 20 次，按 UTC 日期计算，失败和验证也计数。
- 服务连接页可创建限品牌/权限/次数/有效期的 API Key，支持原子轮换和撤销。私有网站外部调用另需平台服务访问权。
- 所有者可创建云端恢复副本、下载、恢复、按品牌清理；恢复或删除前保护当前资产。副本不含模型密钥和成员授权。最近 10 份保留；下载“完整 ZIP”才包含知识库原件与抽取全文，“资料 JSON”只保存记录及路径。
- 最近 100 条操作审计显示时间、执行者、路由和状态码，普通成员无法改写。
- 完整范围与逐项缺口见「设置 → 完整功能与实施」，不再沿用旧演示状态。

## 0.6 任务与后台执行

从「诊断与监测 → 任务与批量执行」创建模型采样任务；内容页也可进入批量生成。选择问题、已配置平台、重复次数和频率。采样发送问题原文，不注入品牌；批量写作保存简报、风格、多版本及当次确认事实快照。

- 每批最多 80 次请求，工作区默认每日模型调用 20 次，超额部分延后。任务保存后进入可执行队列；已安装且在线的执行器会自动领取启用且到期的任务。
- 单条领取有并发锁，问题版本在任务创建时冻结。重复点击不会重复新增同一个任务。
- 明确的供应商 429 限流最多自动尝试 3 次，指数退避；超时或服务器错误可能已计费，进入结果待确认，不自动重复调用。
- 原始返回先保存于执行回执；业务资料保存失败可恢复已有结果，无需再次调用模型。
- 暂停/取消阻止后续领取，已经发出的请求仍可能完成。
- 本机执行器每 120 秒启动一次，每次最多处理 4 条；关闭网页和 Codex 不影响它。电脑休眠、关机、断网时不能执行，恢复后处理下一批；不补造错过时段的样本。
- 任务中心显示最近实际到达服务端的执行时间；5 分钟未响应会提示检查电脑/网络。此证据不证明主机全年在线。
- 浏览器可直接执行当前品牌队列；其他品牌不会被该按钮意外执行。
- 开放 API 的 run 权限独立控制可能产生费用的执行；普通 read/write Key 不能启动模型请求。
- 0.6 初版只备份品牌资产；当前版本已加入完整业务表备份与恢复，任务/调用恢复保护见后续治理说明。

## 0.7 问题挖掘与版本管理

- 在“问题与回答”中选择“AI 挖掘问题”，输入品类、用途或客户需求，生成 3 至 20 个候选。发送品牌名称、行业、种子需求及最多 100 条已有问题，调用一次已配置模型，计入每日配额。
- 候选带主题、意图、标签和 AI 排序理由。排序不代表搜索量或实际推荐效果。选中后加入问题库，自动跳过忽略空格、大小写和标点后相同的问题。
- 支持一行一个问题的批量导入、批量追加标签和意图/标签筛选。
- 编辑会保留最多 100 条版本历史，可对照原版本与新版本。已排队任务和已有回答保留采样时的问题快照。
- “仅当前问题版本”会排除旧版本及早期未记录版本的回答；不会把未知版本补记为最新版本。
- 模型原始输出、请求 ID 与用量保留。返回格式不符合要求时不会造出候选；结果保存中断时可在原表单重试，恢复已有回执而不重复调用。
- 此版自动测试与本地浏览器流程已验证；真实模型扩词的正式工作区验收仍等待可用登录会话。

## 0.8 证据分析与报告

- 报告、品牌洞察、引用来源共用 7/30/90 天、全部记录及自定义日期筛选，可再选平台、Web/App/API 入口、模式及问题版本。日期按 UTC。
- 首段提及排除独立 Markdown 标题；提及按当前登记的品牌名称和别名匹配，需核对同名语境。推荐及引用比例只纳入明确标注过的回答，未知值不当作零。
- 前期为相邻等长窗口，只匹配同问题 ID/版本、平台、入口、模式、地区、语言及模型的组，每组等权计算变化百分点。未记录的上下文会提示，不能保证实际环境一致。
- 主题、意图和未采样问题按当前题库统计。诊断展示具体问题、回答和资料缺口，不把未采样当作效果差。
- 引用 URL 规范化移除锚点、utm 等常见追踪参数，保留业务参数；同一回答对同页只计一次。核对过的重复引用可成为渠道候选，仍需确认行业适配和发布权限。
- 报告可下载 Markdown 及本期原始回答。归档固定保存当时的品牌别名、筛选条件、指标、本期及前期原文，后续改稿不影响旧报告。每份最大 1 MB，超过时缩小范围；最近 50 份在界面展示。
- 报告归档使用独立数据库表，当前工作区 JSON 备份尚不包含任务队列和报告表；可单独下载报告，完整备份治理仍在交付范围内。自动周期报告与外部通知仍待接入。


## 0.9 自动分析与内容质检

- 在「诊断与监测 → 品牌与竞品 → 品牌感知」可批量分析当前筛选范围的回答，保留情感、否定语境、疑似事实冲突和对应原句。
- 在「内容优化」选择批量质检或单篇自动质检。默认跳过已有有效检查的稿件，每批最多 5 条并计入每日模型配额。页面关闭或中断后可恢复未完成批次；服务已返回的回执不重复计费。
- 标题、正文、品牌资料、事实有效性或相关重复稿件变化，会使旧检查提示重新核对。历史快照和模型原始回执保留。
- 支持、疑似冲突、条件遗漏必须引用当前品牌已确认且未过期的事实原文。不存在的引文被排除；引用无效资料的判断改为缺少证据。资料本身仍需真实可靠，逐字匹配不代表独立核实。
- 重复检查使用同品牌内容的三字片段集合相似度及相同长段落，仅报告至少 45% 或存在相同长段落的前 5 篇。它不是互联网查重率、阅读率或原创性证明。
- 结果单独保存，不覆盖人工推荐/引用标签，也不自动将草稿批准发布。审核人可执行检查，编辑不能自行审批，只读成员只可查看已有结果。
- 每批输入最多 60,000 字，最多 150 条品牌事实；超限会提示整理资料。请求结果未知时先核对供应商用量，再决定新建检查。
- 新增 10 组检查测试，整体 70 组通过；浏览器验证批量、原句、重复稿件和改稿失效。此次页面验收使用明确标注的本地模型夹具，真实生产模型质量验收仍需正式登录会话。


## 0.10 告警、复测待办与完整业务备份

- 「诊断与监测 → 告警与待办」保存站内告警。执行器每次调度后自动检查任务失败/未知结果、最新有效分析中的疑似事实冲突、工作区调用配额和同条件官网引用下降；也可立即检查。电脑休眠或网络中断会延后。
- 默认提醒阈值为日调用配额的 80%、官网引用下降 20 个百分点、每期至少 5 条可比较样本、7 天窗口。引用比较截至昨日 UTC，并要求完整上下文和已核对引用。规则由管理员调整，预算告警仅管理员可见。
- 同一异常聚合为一条，可确认知悉；证据变化或消退后重现会重新提醒。消退只表示本次没有触发，可能是样本不足或资料失效，不表示业务问题已解决。没有发送邮件、短信或第三方消息。
- 品牌诊断和告警可直接生成待办，保留来源快照。负责人必须是具有本品牌工作权限的成员或所有者，撤销权限后需重新分配。
- 待办使用待处理、处理中、待复测、待复核、已复核五种状态。最终复核由审核人或管理员完成，需关联创建待办之后的证据并填写结论。新归档的旧样本报告不能伪装成新复测；已复核不自动表示指标改善。
- 云端备份按同一数据库事务包含工作区、任务计划/条目、报告、告警/待办、模型调用回执；下载也包含这些表及校验摘要。密钥、成员授权、API 请求计数和权限不在业务副本内。
- 恢复与品牌清理会等待现有写操作结束并暂时阻止新写入。恢复失败时整批回滚，恢复前保护副本保留。未完成任务计划恢复后暂停；已有结果可恢复，未知调用保留为待核对。发生过的调用记录与用量不倒退，避免恢复旧任务再次计费。
- 旧版副本只恢复品牌资产，任务/报告表保留并暂停活动计划，不把旧副本说成全量备份。保留最近 10 份副本；离线文件导入、异地自动备份及附件存储仍待完善。
- 新增 14 组执行和备份测试；浏览器走通告警转待办、后续证据复核、刷新保留、完整副本创建与恢复。页面验收数据均为本地测试夹具。


## 0.11 品牌产品目录与结构化标记

- 设置 → 客户与品牌：管理员可编辑客户名称、品牌、别名、官网、行业、负责人、品牌介绍和 Logo。修改记录由服务器保存，最近 50 个资料版本可查。
- 产品线：添加具体产品或服务，填写说明、页面、图片、类别和编号；可归档、恢复，最近 50 个版本可查。资料与既有问题/内容保持品牌关联；产品线级问题集和诊断还在扩展。
- 网站诊断 → 结构化标记：Organization 读取品牌资料；Product 读取在用产品；Article 读取所选文章标题，已登记文章 URL 可自动带入，署名/真实日期由页面实际情况填写；FAQPage 可从问答正文提取后核对，也可直接输入“问：/答：”。
- 生成不调用模型、不产生模型费用；快照保存输入、来源、摘要、生成时间和字段检查。可复制可嵌入网页的 script 片段，下载 JSON-LD 或 HTML。当前每品牌上限 100 份快照，受工作区容量限制。
- 来源资料改动后旧快照不覆盖，提示重新生成。归档产品不能生成新标记，旧标记可查看。管理品牌需要管理员；编辑可生成；审核/只读成员可查看和导出已授权品牌的快照。
- 网页检查与粘贴 HTML 检查逐段核对 JSON-LD，显示语法与六种类型的基础字段问题。不是完整 Schema.org 验证器，不验证远程图片、页面真实内容、搜索收录或 AI 引用。客户官网安装仍需其实际部署权限。

依据：[Organization](https://schema.org/Organization)、[Product](https://schema.org/Product)、[Article](https://schema.org/Article)、[FAQPage](https://schema.org/FAQPage)。Product 基础描述不自动具备 [Google 商品摘要条件](https://developers.google.com/search/docs/appearance/structured-data/product-snippet)，不会虚构价格和评价。Google 已宣布自 2026-05-07 起停止 FAQ 富媒体搜索展示，见 [官方更新](https://developers.google.com/search/updates#may-2026)；FAQPage 仍可用于结构化描述。


## 0.12 文档与知识版本

在「品牌知识库」上传 PDF、DOCX、TXT 或 Markdown，文件选择后自动抽取文字。PDF 保留页码，DOCX 按原文段落整理。默认选中前 30 个事实候选，可修改选择后一次导入最多 100 段；自动出处核对逐批执行。解析不产生模型费用，原件和全文不会发送给模型。

- 单文件最多 8 MB，PDF 最多 100 页，正文最多 20 万字、500 个段落/页面；文档原件累计最多 100 MB。事实及历史仍受工作区 JSON 容量限制，超限不会保存残缺记录。
- 原件与完整抽取正文保存到私有对象存储，数据库保存两个独立 SHA-256 摘要和版本关系。只有能访问该品牌的成员可查看、下载。工作区备份恢复保留文档引用，原件继续保留；下载的 JSON 不包含文件字节，异地副本需另行下载原件。
- 上传新版本会保留旧文件和事实，将关联的在用旧事实改为待确认，归档事实保持归档。已保存的原文不能直接改写；早期文本资料也可上传新版。原文中的过短片段或超过 5000 字的单句不作为事实候选，界面显示数量及原因，全文仍保留。
- 事实可关联产品线、设置当地时区的生效/到期时间、归档或恢复，并保留最近 20 个服务器版本。修改内容、出处、产品线或有效期会重新进入待确认；修改内容或出处后解除原文件关联，避免沿用旧证据。
- 未生效、已过期、已归档、缺少内容/出处或未确认的事实，不进入单篇写作、模板、批量写作和自动质检。批量任务执行时再次检查，写作回执固定保存当时的事实版本与有效期。
- 自动通过只表示摘录与保存的抽取文字一致。PDF/DOCX 提取由当前浏览器执行，服务端保存摘要并检查回读一致性；不据此证明原文件版式完整、资料真实可靠或独立通过第三方审核。扫描 PDF、缺字、表格、图片仍需核对原件。

解析库：[PDF.js](https://github.com/mozilla/pdf.js) 6.3.289、[Mammoth](https://github.com/mwilliamson/mammoth.js) 1.13.0；许可证已随站点发布。文件解析、权限、版本、恢复及写作有效期经过自动测试；正式登录会话中的 R2 上传下载验收仍待完成。


## 0.13 自动周报与月报

「证据报告 → 自动周期报告」可分别设置实测/API 的周报和月报，选择平台、Web/App/API 入口、模式及问题版本。管理员和编辑可设置，审核与只读成员可查看授权品牌的计划及归档。

- 每周一 00:10 UTC（北京时间 08:10）到期生成上一完整自然周；每月 1 日同一时间生成上个自然月。报告中的日期和样本边界仍为 UTC，前期对比为等长窗口，月报的前期可能不对应完整自然月。
- 已在线的本机执行器自动处理，每次最多两份报告，不产生额外模型请求。电脑离线时延后，只归档最近一个完整周期，不补造较早期间的样本或报告。
- 原回答、引用和计算条件固定保存；同一计划、相同筛选及周期只归档一次，重复执行复用旧快照。若需要根据新补录资料生成新版，可使用普通「归档当前报告」。
- 「生成上一完整周期」可立即运行一次；即使计划暂停也可手动使用。没有实际回答时保留无样本状态；不推断为平台表现或商业结果。
- 保存失败会留下原因，自动执行至少延后一小时；恢复业务备份后，报告计划也会暂停，需要核对后重新启用。此功能只生成站内归档，邮件、飞书等外部发送仍待指定渠道和授权。
- 自动测试覆盖周期边界、并发幂等、原子回滚、角色隔离和恢复暂停。正式执行器已接调用链；生产计划首次到期生成仍需要工作区实际设置及回执验收。


## 0.14 发布后复测与首次引用提醒

「发布与复测」登记新链接时默认启用每天复测，可改为每 6 小时或每周，也可暂停；旧记录不会自动开启，编辑时可以选择启用。引用观察窗口支持最近 7、30、90 天，日期按 UTC。活动页面每 30 秒刷新复测进度。

- 自动执行器在模型队列空闲时一次检查一篇，复用现有专用执行权限，不产生模型调用。电脑离线、休眠或队列繁忙时延后；网页失败或疑似登录/验证码页面至少一小时后再试。
- 每次保存网页 HTTP 结果、实际响应地址、标题、正文字符数、抽取文本指纹和摘录。HTTP 200 只记为收到响应；正文太少会提示可能需要浏览器渲染，标题未匹配也明确显示。最多读取 2 MB HTML，抽取文本指纹对应本次最多 15 万字正文，详情显示前 1800 字。
- 引用与网页访问相互独立。只匹配已保存回答中实际的文章 URL，移除常见追踪参数与锚点，保留业务参数；每个回答只计一次。核对过引用的回答、尚未核对的链接匹配、已标注推荐分别计数，API 与导入实测分别展示。未来时间、失败或其他品牌的回答不纳入。
- “首次记录到文章引用”指工作区首次保存的已核对匹配。提醒同时保留发现时间、原回答采集时间、平台和题目，可打开当次复测证据；不推断全网首次引用，也不表示文章带来了推荐或转化。已知悉提醒不会因重复检查相同引用而重开。
- 固定快照包含当时的品牌资料、页面摘录、样本口径和每种数据类型最多 50 条引用证据摘录，优先保留最早已核对证据及最近记录；额外匹配仍计数并显示省略数量。每条摘录最多 1500 字，保留完整回答 SHA-256 与最多 3 个实际匹配 URL。当前完整回答可另行查看或从报告导出。
- 重复请求复用同一记录；并发检查只抓取一次。请求过期后重试，迟到的旧返回不能覆盖新结果。检查途中修改链接或条件，旧结果仅作历史，不更新新链接的首引用提醒。
- 最近 100 次复测可查看和逐条下载；全部已存记录纳入业务备份，每工作区最多 5000 条，达到上限会显示原因并暂停尝试一小时。恢复副本后自动复测关闭，需核对后启用；删除品牌会一并移除当前复测记录，删除前保护副本仍可恢复。

本功能复查公开静态网页与工作区已有回答，尚未替代 AI 消费端的新一轮同题采样，也不证明搜索收录、公开发布或商业效果。JS 渲染、认证页面、消费者平台新采样与发布适配器仍分别接入。

## 0.15 助手连接

服务连接新增 MCP 地址、助手密钥入口和可下载 Skill。官方 SDK 同时处理新旧协议，12 个工具覆盖品牌/问题、诊断、稿件与出处、任务查询/创建/控制及固定报告。私有站点授权保留，工具按品牌、权限、有效期和请求额度执行。

任务创建/恢复需要写入和执行权限；沿用已有队列、每日模型配额和业务状态。只读查询不调用模型，助手无法把稿件自动审核或发布。报告和稿件支持分段读取，Skill 说明要求核对版本摘要及任务回执。

自动化合同测试通过不代表已连接用户的外部助手。生产外部客户端首次授权、真实模型任务和消费端采样仍分别验收。下载说明见服务连接中的「接入说明」。


## 产品线运营

在“客户与品牌 → 产品线”中选择“问题 / 稿件 / 诊断”可直接进入对应产品范围。问题支持按产品线新建、导入、批量分配和挖掘；相同文字在不同产品下可以分别维护。分配变更会产生问题新版本。

新任务保存当时的产品和问题版本。调整题目归属或重命名产品后，旧任务与回答仍保留原快照。导入的历史回答只有具备对应版本和时间依据时才记录归属，否则显示“归属未记录”。归档产品停止创建新稿和新任务，已有历史资产可查看。

写作使用当前产品事实及品牌通用事实。内容自动检查也只接受同产品或品牌通用证据；旧检查因规则变更显示需重做。自动检查仍是证据辅助，不自动批准发布。

洞察、信源和报告支持全部产品线、单个产品、品牌通用、归属未记录筛选。产品覆盖表显示当前题集、已存稿件及本期回答；提及率衡量这些题目下的品牌表现，不等于产品名称提及率。每个产品可独立配置周报/月报，归档保留当时名称与范围。


## 转化归因与 CRM 导入

入口：“效果报告 → 转化归因”。访问、客户自述、咨询、成交使用不同记录类型。可直接登记一条，也可上传 UTF-8 CSV 或 JSON 数组；上传后自动识别常见中英文列名，未映射列不会上传。预检展示新记录和重复记录数量，确认后整批保存。每次最多 200 条，每工作区最多 5000 条；JSON 导出包含当前范围及关联证据。

使用 CRM 内部客户编号，不填写联系方式。来源系统名称和记录编号共同去重；相同编号但内容不同会拒绝整批。记录错误时作废并填写理由，再用新编号补录更正，不覆盖历史。

咨询可关联访问或客户自述，成交可关联咨询、访问或自述。必须是同品牌、相同且非空的客户编号，来源时间不晚于转化；仅在所选 7/30/90 天窗口内归因。不自动按姓名、浏览器指纹或相近时间猜测关联。来源记录即使早于报告开始日期，只要在回溯范围内仍可作为证据。匿名访问缺少客户编号时保留访问记录，不自动拼接到成交。

引荐日志支持的转化、客户自述转化、来源未确认的转化分别计算。引用不算访问；访问记录数量不是独立访客数。成交金额按 CNY/USD/EUR/GBP/HKD 的两位小数或 JPY 的整数保存，不换汇，不当作财务营收或因果增量。

报告中心实时显示同日期和产品范围的转化结果；模型平台、入口和 API/实测筛选不限制商业事件。归档、Markdown 导出及自动周报/月报保留当时的记录与关联链（默认回溯 30 天）；以后作废来源不改写旧报告。完整业务备份覆盖该模块。

客户网站或 CRM 后端可调用开放 API 同步；应用密钥仅放在受控后端。此私有站点尚未配置客户网站公开埋点，也未取得第三方 CRM 授权，因此界面不会宣称已经获得真实网站流量或成交数据。

## 来源分类、趋势与媒体候选

进入「监测 → 信源」选择日期、平台、产品范围，再用来源分类或文字查找。域名和页面均可查看原回答、每日引用比例与首次/最近观察。柱状图只显示有样本的日期；灰线为已核对分母下的零引用，问号表示分母尚未核对。来源筛选仅影响列表，趋势页注明当前口径。

「趋势与核对 → 编辑来源核对」保存类别、行业相关性、发布条件及依据。官网默认按品牌官网精确域名匹配；其他分类需要核对。域名记录可被页面独立核对覆盖。每品牌最多 100 个核对来源，每来源保留 40 次修改；达到限制会停止新增，不丢弃旧历史。只读与审核成员可查看，编辑及管理员可保存。

候选由分类、明确行业相关性及至少两条已核对回答共同产生，依次按问题、平台、回答覆盖排序。页面标为不相关或不可发布后，其证据不会继续计入域名候选。未知发布条件会明确显示，不代表已有媒体授权。旧归档保留当时分类和引用证据；自动周月报同样记录。来源列表最多显示 100 项，候选显示 20 项、趋势显示最近 90 个采样日，完整结果可随证据报告导出。

## 站内检查与抓取限制

进入「网站诊断」填写起始页，选择 1 / 5 / 20 / 50 页上限。任务先读 robots.txt，再读取起始页、同源 Sitemap XML 和发现的站内链接。每步保存进度；当前页面可连续执行，离开页面后由本机执行器空闲时接续，电脑休眠或离线时不保证推进。可以暂停、继续或停止；已经发出的公开读取请求可能继续结束，但暂停后的迟到响应不会覆盖进度。

详情包含响应状态、内容类型、跳转、页面标题/描述、规范链接、索引指令、JSON-LD 基础检查、正文摘录、抓取规则命中行、重复标题及每个 URL 的发现路径。下载 JSON 保存当时记录。允许抓取、HTTP 200、允许索引、实际搜索收录和 AI 引用各自独立；本模块没有实际索引后台数据。

当前仅检查公开 UTF-8 静态 HTML：不执行 JS、不登录，不跟随跨源跳转；单资源最多 512 KiB、同源资源最多 200 个、站点地图最多 5 份及两层子索引，地图暂不处理 gzip 压缩文件。每品牌同时最多 2 个进行中任务，工作区最多保存 200 次检查。超过页面或发现限制会保留未检查范围，不能当成整站完成；记录超过容量会停止并保留原结果。

robots.txt 返回 404/410 时注明未发现文件；拒绝访问、服务错误、非纯文本或读取失败会停止自动遍历，用户仍可使用独立单页检查。抓取规则解释来自本次原文，不证明平台实际行为。备份恢复后的进行中检查默认暂停，避免意外重新抓取。


## 0.22 完整离线备份

在“设置与完整功能 → 团队与数据 → 备份与恢复”创建云端副本后，选择“完整 ZIP”。包内包含业务记录、知识库原件、完整抽取文本和校验信息。缺少原件、原件变化或超过限制时会说明原因，不将不完整文件标为备份成功。

导入时选择同一工作区导出的 ZIP，核验签名、品牌及附件后保存为云端恢复副本。上传中断可重新选择同一包继续；保存副本不会覆盖当前工作数据，恢复入口仍需明确选择。原服务密钥、范围限制、任务恢复保护及暂存清理见 [离线备份说明](离线备份说明.md)。


## 0.23 回答快照与附件

在回答详情点击“添加截图 / 公开过程”，可保存 PNG/JPEG/WebP、PDF、TXT/Markdown，并填写实际采集时间、回答链接、公开检索词和过程摘要。服务端固定当时的回答全文、问题版本、引用与平台模式；后续回答变化会提示旧证据，不改写原快照。原件按品牌授权下载，报告归档保留证据编号和摘要，完整 ZIP 包含原件与快照。保存附件不会自动通过引用或推荐审核，消费端自动采集仍待接入。详见 [回答证据说明](回答证据说明.md)。


## 0.24 从文件导入题库

在“问题与回答”点击“文件导入”，选择 CSV、TSV、TXT 或 JSON。支持 UTF-8、GB18030 和 UTF-16 LE；先核对问题/主题/意图/标签/产品线对应列，再预检并勾选有效问题。每次最多 500 行，服务端再次去重后将问题和回执一并保存。已有问题不覆盖，导入不触发模型调用。详情与接口见 [问题文件导入说明](问题文件导入说明.md)。

## 0.25：跨页统计范围

概览、问题与回答、品牌与竞品、引用来源、效果报告使用同一套日期（UTC）、产品线、平台、入口、模式、问题版本和数据类型筛选，默认近 30 天。五个统计页面之间的导航保留已应用的条件；链接和浏览器前进/后退也保留 API / 导入类型。品牌切换保留通用统计条件并清空旧品牌的产品范围。

问题文字、主题、标签、意图和信源分类仅用于本页列表，不自动改变全局报告范围。历史回答始终按采集时的产品归属计算，可能没有对应当前所列问题；“查看本期全部回答”用于核对完整分母。品牌待办和工作流程仍显示整个品牌的进度。概览提供产品线覆盖及最近 14 个有样本日期的趋势，展开可看全部日期的分子/分母；未知推荐分母不会画成零。

无效日期或已经删除的产品链接会显示重置入口。自动测试验证统计与导航逻辑；正式登录后的业务数据验收仍待完成。

## 0.26：Excel 问题库直接导入

“文件导入”现支持 XLSX，可选择工作表与表头行号。跳过空白行并保留真实行号；隐藏表和隐藏行有提示。映射字段中的公式与 Excel 错误值进入逐行错误列表，可先导入其余有效问题。工作表名称与表头行随回执固定保存，重试和业务备份恢复时保留。

每次仍为 1–500 个问题、最多 40 列和 2 MB 文件。旧 XLS、XLSM 及加密文件需要另存为普通 XLSX 或 CSV。详见 [文件导入说明](问题文件导入说明.md)。

## 0.27：优先处理清单与批量待办

工作台效果概览可进入“优先处理清单”；品牌与竞品洞察新增“优先处理”页签。沿用当前日期、平台、入口、模式、产品和数据类型范围，再对照当前问题版本及采集时产品归属计算缺口。旧版、归属不明和未对应题集的记录单独说明。

规则先区分证据核对、资料准备、采样覆盖，再按稿件状态安排创作、审核、发布和复测。3 条是工作队列的采样阈值，不是统计显著性、市场热度或效果保证；同类按未提及比例、决策/比较/了解/使用意图、问题编号排序。品牌通用或本产品资料可作为准备度线索，但是否支持某个问题仍需核对。已归档产品不安排新工作。

可逐项分配负责人，也可为当前类型的前 50 项批量建立待办，默认负责人为工作区所有者。同一观察范围和依据复用已有自动事项；依据或窗口变化可形成新的事项。批量操作在一个数据库事务中保存，旧依据会被拒绝，网络中断后可重试原批次。只建立工作记录，不调用模型、不发布、不自动宣布改善。

待办保存当时的原因、指标、问题版本和证据编号，来源为“问题处理机会”。可继续发起关联复测；机会待办限定其原问题与产品归属，复测结果返回后仍需核对。清单随 Markdown 报告及固定归档保存，也可完整导出 JSON。资料和稿件状态取报告生成时，回答使用指定历史窗口，两者含义在页面中说明。


## 0.28：DSO 关键词与内容实验室

从「内容优化 → DSO 内容实验室」进入。抖音与小红书关键词可记录产品范围、来源、观察日期和原始依据；可选指标必须同时保存单位、窗口与方法，没有指标就保持空缺。选择同平台、同产品的关键词与有效已确认事实后，可通过已连接模型生成抖音脚本或小红书图文草稿，自动填入标题并保留原始回执、用量及事实/关键词快照。

草稿可编辑、送审、审核、退回与完整导出。依据更改或失效会显示提示并阻止通过旧稿；内容修改重新回到草稿。DSO 记录单独保存，不计入 GEO 监测指标。DSO 默认每日 10 次模型调用（UTC 日，含失败），所有者可调整到 0 以关闭；GEO 保持原有独立限额。这是调用次数控制，不是供应商金额账单。

新增 15 组专项测试，全套 339 项通过。真实业务会话下的模型质量、平台授权采集、视频制作与发布仍待验收，当前不会把脚本标成已成片或已发布。见 [DSO 使用说明](DSO使用说明.md)。


## 0.29：自有 WordPress 网站发布

「发布与复测」新增网站连接。管理员填写 HTTPS WordPress 地址、专用用户名与 Application Password 后，可验证当前账号的编辑/发布权限。已审核稿件可以直接创建网站草稿；确认后发布，保留文章编号、真实 URL、远端状态及提交快照。发布回执自动转为发布记录并启用 24 小时网页复测，无需逐篇复制 URL。

重复创建请求按稳定编号恢复；网络中断不会自动重发，通过远端文章编号或唯一匹配的提交标识核对结果。远端或本地稿件变化会阻止继续发布旧稿；已发布文章转回草稿或内容变化时，核对回执会同步提示并暂停自动复测。恢复备份保留外部执行回执并停用网站连接，避免历史资料恢复触发外发。

19 组新增发布测试通过；同时修复原回调容量测试中随机摘要以 d 开头时被测试清理语句误删的问题。全套 358 项通过。接口合同使用受控 WordPress 响应测试，真实客户网站尚需授权并完成首次发布验收。图片/复杂 Markdown 不自动渲染，社交平台发布仍未接入。见 [WordPress 发布说明](WordPress发布说明.md)。


## 0.30：扫描件与图片 OCR

知识库的「上传文档 / 图片」支持 PNG、JPEG 和扫描 PDF。默认自动识别没有文字的 PDF 页；如果扫描页仅含少量可提取的页眉，请选择「整份 PDF / 图片使用 OCR」。可选简体中文、英文或混合语言。切换模式或语言会重新解析；识别中可以取消，不会保存半成品。

- 使用 Tesseract.js 7.0.0 在当前浏览器本地识别，不调用付费模型、不向外部 OCR 服务发送原件。首次运行从本站下载固定版本识别组件；服务端仅从固定公开包地址取得组件并核验 SHA-256，缓存到对象存储。组件缓存与客户文件隔离。依赖下载失败会报错，不退回第三方文档上传。
- 单文件 8 MB、正文 20 万字、PDF 100 页；其中 OCR 最多 20 页，图片最多 1200 万像素且边长不超过 10000。PDF 图像渲染最长边最多 2400 像素；低清、倾斜、手写和复杂表格效果有限。一次识别最长 8 分钟，可取消并拆分重试。
- 预览与已存原文保留页码、识别方法和文字识别置信度。置信度不是事实真实性评分。OCR 摘录默认待确认，即使与识别文字一致，也需要审核角色对照原件确认。混合 PDF 中完整匹配的原生文字仍可自动核对出处。
- 点击保存后，原件、识别全文及方法元数据进入私有工作区，适用现有品牌权限、版本和完整 ZIP 备份。切换工作区或品牌会使旧解析结果失效。
- 已用实际中文 JPEG、英文 PNG 和扫描 PDF 像素验证本地引擎；已测试资源完整性、取消、工作区切换、上传、版本恢复与 OCR 不自动确认为事实。正式登录浏览器中的首次 OCR 上传仍待验收，不能把自动测试视为真实客户文件验收。

组件与许可：[Tesseract.js](https://github.com/naptha/tesseract.js)（[随站许可证](../vendor/Tesseract-js-LICENSE.md)）、[tesseract.js-core](https://github.com/naptha/tesseract.js-core)（[随站许可证](../vendor/Tesseract-core-LICENSE.txt)）。固定语言包 @tesseract.js-data/eng 与 chi_sim 1.0.0 使用 best_int 模型；[英文包说明](../vendor/OCR-eng-README.md)、[中文包说明](../vendor/OCR-chi_sim-README.md)及包元数据随站提供。


## 0.31：竞品语义分析与复核

在「品牌与竞品洞察 → 竞品对比」登记竞品名称、别名、官网和消歧描述，例如行业、产品或容易混淆的同名对象。可编辑、归档和恢复；归档资料不再参与当前分析，历史快照保留。分析每批最多 2 条回答、含当前品牌最多 20 个品牌，输入最多 60000 字；按当前日期/平台/入口/模式/版本/产品筛选执行，计入每日 GEO 模型调用额度。

- 模型分别建议「本品牌 / 未提及 / 同名其他对象 / 无法判断」与「明确推荐 / 未明确推荐 / 无法判断」。身份和推荐引文必须能在原回答逐字定位且包含登记名称或别名；结果缺失、重复、引用伪造及无效编号会提示。字面匹配并不独立证明语义正确。
- 「分析与复核」显示完整回答、模型建议和可修改字段。所有者、管理员、审核人可一次保存本批全部判断；编辑可分析，不能确认；只读成员只可查看。复核保留操作者、时间、版本和原句，每份分析最多 50 次复核。保存使用固定请求标识和版本检查，重试不重复创建复核。
- 提及分母只含身份已知的复核记录；推荐分母只含身份、推荐均已知的复核记录。未复核与无法判断排除，分母为零显示不可计算。明确未出现或同名其他对象记为未推荐。位置仅接受明确推荐且有阿拉伯数字编号、同一行品牌及声明优先顺序的上下文；普通清单不应填写。平均位置只用有序推荐样本，不是行业排名。
- 竞品语义统计与原有品牌概览的人工回答标签独立保存，不覆盖原标签。报告 JSON、Markdown 和固定归档包含复核分子/分母、原句、时间与回答编号。后续修改不改写已归档报告。
- 回答文字、问题版本或品牌/竞品身份资料变化后，旧判断失效。新的分析会替代该回答的旧分析作为当前候选，未复核的新结果不会沿用旧复核。暂停和恢复批量分析绑定工作区与品牌；同一已完成请求先恢复回执，不重复调用模型。
- 已通过引文校验、权限、并发、幂等、付费回执恢复、未知分母、归档、备份恢复和界面逻辑自动测试。模型测试使用受控返回，正式登录账号下的真实消歧/推荐质量、用户流程与业务样本验收仍待完成。


## 0.32：需求热度来源数据

在「诊断与监测 → 需求数据」导入来源方导出的 CSV、TSV 或平面 JSON 数组。填写来源名称、入口 URL、来源类型、平台、地区、语言、取得日期、统计窗口、单位、计算/估算方法和使用授权说明。搜索量、相对指数、搜索展现、搜索点击分别保存；相对指数限定 0–100 且必须注明归一化批次。来源类型与授权说明是用户登记，不代表系统已独立验证授权或来源真实性。

- 文件选择后自动建议列映射；每次最多 500 行，支持 UTF-8、GB18030 和 UTF-16 LE。默认窗口可被行内窗口覆盖，列表显示实际选中观测的最早/最晚日期；中间可能有缺口，不据此推断连续覆盖。
- 点值与上下限区间二选一。负数、无效日期、未来窗口、缺失值、NA、<1、重复行与跨品牌问题 ID 会提示错误，不将其自动填零。默认勾选通过预检的行，可修改选择后整批保存。
- 保存解码后的导入文本、SHA-256、原文件行号、选中记录、来源口径、导入人和时间。可选关联问题 ID，保留导入时的问题文字与版本。未选中行与未映射列也在完整文本快照内，上传前请按品牌拆分文件，并移除其他客户、无关或敏感资料。这里保存的是导入文本，不是原始二进制文件字节。
- 同一导入请求重试恢复原回执，不重复建批次。资料不可原地改写；更正时作废旧批次并导入新批次。作废和恢复均需要原因，保留最近操作历史；最多 50 次状态操作。每品牌最多 100 批，单个保存快照最多 900 KB。文件最多 2 MB，但上传 JSON 请求还受 1 MB 上限约束，文本较大时需拆分。
- 「来源与数值 → 前期对照」仅比较同来源、平台、地区、语言、指标、单位、方法和归一化批次下的相邻等长窗口。关键词去首尾空白后须逐字一致，关联问题也必须对应。区间不取中点，前期为零不计算相对涨幅，作废或不同口径的数据不参与对比。指数变化不解释为需求次数增长。
- 可导出 JSON、Markdown 与导入文本。批次及状态历史进入现有业务备份，品牌删除受恢复副本保护。当前仅提供独立需求数据导出，不把它混入 AI 回答提及率或行业榜单。
- 已通过格式、来源口径、窗口、区间、零值、权限、API、并发、幂等、容量、备份恢复与界面逻辑测试。测试使用明确标记的夹具，尚未接入用户真实获授权的来源文件或自动数据源，正式浏览器验收也仍待完成。

外部系统可使用已授权应用 Key 调用 `/api/v1/demand`、`/detail`、`/compare`（read）以及 `/preview`、`/import`、`/status`（write）。所有请求需要明确 brandId，仍受 Key 的品牌范围、到期与额度约束。完整字段见 [需求数据接口说明](需求数据接口说明.md)。


## 0.33：行业题集样本榜单

在「品牌与竞品洞察 → 行业基准」建立榜单，标题自动填入当前品牌名称。选择 3–50 个当前问题、2–20 个候选品牌，填写行业范围、题目选择及取样方法、来源说明和 UTC 起止日期。榜单使用自己的题集与窗口，不沿用其他洞察页筛选。无需额外模型调用。

- 先取得原回答，并在「竞品对比」完成身份及所需推荐判断的复核。只有当前原文、问题版本与候选资料下的有效复核才参与。未复核、无法判断、失败、演示、问题文字或版本变化、缺少采集条件的回答会列出排除原因；未知不当作零。
- 导入实测与模型 API 测试分开，平台、Web/App/API 入口、模式、地区、语言及已记录模型分别分组。每条纳入回答必须对全部所选候选品牌有已知复核，保证共同分母。每组还需覆盖全部选中题目，并达到设置的最少共同回答数（3–1000，默认 10）；不满足时保留缺口，不生成排名。
- 每题先计算正例比例，再对所选题目等权平均，避免某一题重复次数多而占据更大权重。并列按精确分数比较，使用 1、1、3 竞争排名；页面另列原始正例/共同回答数。显示百分比保留三位小数，名次不按显示舍入值判断。
- 预览不写入。保存时再次核对原文、题集、候选与复核资料，变化则要求重新预览。固定保存计算参数、候选资料、问题版本、原回答、引文、复核人/时间/编号、附件索引及 SHA-256，可导出 Markdown 与 JSON。后续修改不重写旧榜单，重试原请求不重复建立。
- 所有者、管理员和编辑可建榜单；审核人和只读成员可查看、导出已授权品牌的快照。资料纳入备份与恢复，品牌删除一并清理并先保留恢复副本。每品牌最多 100 份快照，窗口最多 1000 条候选回答，快照原文最多 880 KB，超过时明确提示缩小范围。
- 这是所选题集、候选范围和采样方式下的样本表现，不代表全行业普查或官方排名；最少样本数不是统计显著性，模型未披露时也不能证明底层模型相同。真实行业题集与代表性样本、正式浏览器流程仍待验收。

新增 15 组专项自动测试，覆盖每题等权、精确并列、共同分母、题集缺口、采样分组、旧依据失效、权限、并发、重试、备份恢复、容量和界面作用域。测试为受控夹具，不会写入生产品牌或冒充真实行业样本。接口见 [行业榜单接口说明](行业榜单接口说明.md)。


## 0.34：工作区自动备份

「设置与完整功能 → 团队与数据」增加自动备份。现有后台执行器遇到有品牌资料的工作区时，首次自动建立数据库保护快照，之后默认每 24 小时一次、保留 7 份。不是全天候云端时钟：本机执行器离线会延后；重新上线只保存一份当时的快照，不伪造漏掉时段的历史副本。没有品牌资料时不建空副本。

- 所有者可在首次执行前暂停，也可选择每 6 小时、24 小时或 7 天，保留 3–30 份自动副本。启用或改变周期后，下次心跳即到期；只调整保留数量不会立即创建副本或清理旧副本。管理员可查看计划和历史，其他角色无权读取整个工作区的备份设置。
- 手动备份、删除前保护和恢复前保护单独保留最近 10 份。自动副本不会占用这 10 个名额，只有新副本成功后才按保留数量清理；失败保留最近成功副本。完整离线导入的副本归为手动副本。
- 保存品牌资料及业务表在同一数据库事务内完成。并发心跳通过 5 分钟租约只领取一次；崩溃后租约可恢复。丢失成功响应会查询原副本回执，不重复创建。保存失败 5 分钟后重试，连续 5 次失败自动暂停并记录原因；修复后重新启用。
- 计划修改使用版本检查和稳定请求编号，暂停或变更计划可取消尚未写入的旧领取。已完成副本不会回滚。最近 30 条成功/失败记录可在页面查看；执行器本机状态仅保存摘要，不输出工作区正文或凭据。
- 恢复任意历史资料后暂停自动备份，保留现有计划历史，所有者需核对后重新启用。自动备份计划不随业务快照回滚。
- 这些是同一站点数据库中的恢复副本，包含附件索引，但不复制原件、密钥或成员权限。它不等于异地容灾，也不能覆盖存储服务整体故障。需要独立副本时使用「完整 ZIP」下载原件与业务记录；异地自动备份仍在完整范围内。

新增 13 组专项自动测试，覆盖首次保护、离线补当前快照、暂停、权限、并发、租约恢复、事务回滚、有限重试、丢失回执、独立保留、恢复后暂停和前端工作区隔离。正式浏览器设置操作仍待解锁后验收。


## 0.35：网站稿件排版与预览核对

WordPress 创建草稿前自动生成排版预览，保留 Markdown 标题、嵌套列表、表格与对齐、引用、强调、代码块、HTTP/HTTPS 链接、邮箱和页内链接。HTTPS 图片保留外链；不上传媒体库，不自动设置特色图。相对地址和不支持的链接格式保留原文，无效或非 HTTPS 图片用替代文字提示；原始 HTML 不执行，作为文字显示。

预览从服务端当前已审核稿生成，不调用模型或写入 WordPress。提交时重新计算稿件/事实快照与排版摘要；版本不一致则停止，需重新打开创建窗口。成功回执保存排版版本、正文摘要和实际提交 HTML。后续核对与发布仍使用原提交内容，升级解析器不会改写历史草稿或回执。

预览位于受限框架中，不执行脚本、不提交表单、不加载外部图片，链接也不跳转。图片在预览中显示替代文字，是否可访问需在目标网站检查；目标主题也会影响实际样式。切换稿件、品牌或工作区后不会显示旧请求的预览结果。原始稿件可在回执详情中展开查看。

采用 [markdown-it 15.0.2](https://markdown-it.github.io/markdown-it/)（MIT，许可与依赖许可随站保存），固定依赖版本并关闭原始 HTML。新增 13 组格式、链接、图片、注入防护、容量、作用域、预览失效、提交一致性和历史回执兼容测试。生产依赖审计未报告已知漏洞；正式浏览器与客户 WordPress 实账号首次发布仍待验收。

## 0.40 助手读取原文与后台检查

助手接口增加五个工具，共 17 个；只读 Key 可见其中 13 个，不会启动模型。已授权助手可以通过对话完成“读取回答或稿件 → 创建后台检查 → 查询进度 → 阅读结果与依据”。

- `geo_list_answers` 按报告相同的日期、平台、入口、模式、产品和问题版本筛选；消费者实测与模型 API 分开。`geo_get_answer` 分段读取完整原文、引用链接和附件索引，未知引用不当成已确认无引用。
- `geo_create_check_task` 为品牌感知、内容质检或竞品分析建立后台任务，需要写入与执行权限。同一逻辑操作保持编号及参数不变，可找回丢失的创建回执；跳过有效结果、资料变化检查与配额规则同工作台。
- `geo_list_checks` 列出回执及资料失效状态。`geo_get_check` 分别读取结果及人工复核、当时原文与事实快照、模型原始返回。长记录不会静默截断，沿 nextOffset 继续，拼接前核对 textHash。
- 检查建议不会修改稿件审核、推荐或引用标签。格式错误的模型输出可查看，但不会冒充有效检查。
- 客户首次接入仍需专用应用 Key 和私有站点访问授权；本版本的本地官方客户端验证不代表生产客户端已获授权。下载的 Skill 已包含完整操作流程。

## 0.41 知识库本地语义检索

进入“品牌知识库 → 语义查资料”，用自己的问法查找相关事实和原文。默认使用当前品牌有效且已确认的事实，以及勾选的当前原文；可以取消不需要的文档，或明确包含待确认、过期和历史资料。检索范围是当前品牌全部产品资料，原始文档没有按产品自动拆分。

- 中文检索模型在本机浏览器运行，不调用付费推理 API，不向模型服务发送客户原文或问题。首次下载固定模型和运行组件约 39 MB，后续可复用公开组件缓存；原文读取仍需工作台登录和网络。
- 原文按保留重叠的短片段检索，最多 2000 段。超出容量时提示减少文档，不把局部搜索当成完整结果。通常展示前 10 条候选，相同摘录去重，每个来源最多两段；排序分数不是真实性概率，不保证候选一定回答问题。
- 每条候选保留逐字原文、事实/文档编号与版本、页码或段落、有效状态；OCR 内容显示置信度并提示核对原件。原文命中不会自动变成已确认事实。
- 完成后核对资料是否变化；变化时结果标为旧快照，需重新检索。可导出本次问题、选择范围、资料版本、模型版本和原文依据。
- 搜索期间可以停止。关闭检索面板会释放客户原文与向量的内存缓存；不把客户检索索引保存在浏览器长期存储。公开模型组件仍可缓存。
- 使用固定版本 BGE-small-zh-v1.5 中文模型及 Transformers.js；首次组件下载失败会显示原因，原有关键词筛选仍可使用。实际 WASM 已通过 4 组中文改写问题验证，该小样本不代表所有行业的检索质量；正式浏览器验收仍单独记录。

## 0.42 复制回答时整理来源链接

在“保存平台实际回答”的原始回答框粘贴带链接的内容，会自动列出链接候选；也可以点击“从回答文字提取链接”，处理 Markdown、引用式链接和完整 URL。勾选平台实际引用的链接，点击“填入选中链接并去重”即可批量合并到清单。复制时保留的链接标题会随回答保存。
