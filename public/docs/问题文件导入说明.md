# 从文件导入客户问题

适用：观引 GEO 0.26。入口：问题与回答 → 文件导入。原“一行一个问题”的粘贴入口继续保留。

## 支持的资料

| 格式 | 结构 |
|---|---|
| XLSX | 可选择工作表和表头行；支持共享文字、行内文字、富文本和空白行，保留真实行号。隐藏工作表标记显示；隐藏数据行仍参加预检。 |
| CSV | 第一行表头，默认逗号；可选择分号或制表符。支持带引号、引号内换行及双引号转义。 |
| TSV | 第一行表头，制表符分隔。 |
| TXT | 每个非空行一个问题，保留原行号。 |
| JSON | 问题文字数组、平面字段对象数组，或含 questions 数组的对象。标签可为文字数组。 |

文件不超过 2 MB、500000 字、40 列，每次 1–500 条记录。文本格式支持 UTF-8、GB18030（常见中文 CSV）及 UTF-16 LE。XLSX 自动读取编码，最多 30 张工作表；旧 XLS、带宏 XLSM 和加密文件请另存为普通 XLSX 或 CSV。

XLSX 只读取文件中保存的原始值；不会执行公式、宏、脚本或访问外部链接。选中字段含公式（包括有缓存结果的公式）或 Excel 错误值时，该行进入错误列表，先在表格工具中复制并粘贴为值或修正错误。未映射的备注公式不影响其他字段。日期和数字的显示格式不复制，合并单元格不自动向下填值，导入前应核对预检内容。

工作簿最多 512 个 ZIP 条目、单个展开文件不超过 8 MiB、总展开量不超过 24 MiB；校验文件长度、CRC 与实际展开大小。过大的图片或无关表请先移除。文件读取留在浏览器内，只有选中的字段及工作表名称/表头行号提交到服务端。

## 字段核对

选择文件后自动建议“问题正文、主题、用户意图、标签、产品线”对应列，可手工调整。同一列不能分配给两个字段，问题正文必须指定；未映射的列不会上传。

主题、意图、标签和产品列缺省时采用表单默认值。用户意图为“了解、比较、决策、使用”。标签可用逗号分隔，最多 10 个，每个 30 字。问题正文最多 500 字，主题最多 60 字。产品列支持当前品牌在用产品 ID 或唯一名称，ID 优先；明确填写“品牌通用”或 @brand 可不归属某一产品。不会猜测其他客户的产品，也不会自动新建产品目录。

预检展示源行号、正文、解析后的产品及结果。CSV 中包含换行的单元格按实际起始行号显示；JSON 的行号为数组项序号。错误行说明原因，文件内及当前产品范围中的重复项单独显示；只对可新增项提供勾选。可下载预检明细，修改原文件后重新导入。

## 保存与重试

默认勾选所有可新增项，也可选择其中一部分。全部新增项超过当前工作区容量时仍可预览，减少勾选数量后提交。实际保存再次检查最新题库、产品状态和配额；已有问题保持原主题、标签、版本和历史，不被文件覆盖。

一次提交只保存所选问题及其回执，数据库事务失败时整批回滚。重复操作同一请求恢复原回执；另一批导入相同问题会按品牌 + 产品范围 + 规范化正文去重（忽略大小写、空格和标点）。同一句问题可以分别属于不同产品。

网络中断后保持当前选择重试。第一次提交后选择固定，避免把同一请求误用于其他内容；如需调整，请重新打开文件预检。相同请求编号改写内容会被拒绝。导入不会自动创建监测任务、调用模型或发布内容。

“导入记录”展示当前品牌最近 50 次文件导入，可查看和下载固定回执：文件名、XLSX 工作表名/表头行、时间、提交者、源行号、实际字段、结果与问题 ID。后续改版不会改写回执；完整历史随业务备份保存。回执证明导入操作及内容，不证明文件来源的真实性。原文件本身不在此流程保存。

## 接口

私有站点的外部调用需要 Sites 服务访问授权及限品牌应用 Key。POST 需要 write，GET 需要 read。

- `POST /api/v1/question-imports/preview`：逐行预检，不写入题库。
- `POST /api/v1/question-imports/commit`：提交选中行，原子保存题库与回执。
- `GET /api/v1/question-imports/receipts?brandId=...`：最近 50 份回执摘要。
- `GET /api/v1/question-imports/receipt?brandId=...&id=...`：完整回执。

POST JSON：

```json
{
  "id": "稳定的 UUID 请求编号",
  "brandId": "实际品牌 ID",
  "sourceName": "客户问题.csv",
  "format": "csv",
  "defaults": {"topic": "未分组", "intent": "了解", "tags": [], "productId": ""},
  "rows": [
    {"row": 2, "text": "产品如何使用？", "intent": "使用", "tags": ["上手"], "product": "品牌通用"}
  ]
}
```

XLSX 请求使用 `format: "xlsx"`，并提供 `sheet: {"name": "客户问题", "headerRow": 3}`。若某行映射字段含无法采用的单元格，传 `importError`（不超过 500 字）使其进入错误列表，不能提交该行；工作表信息计入请求指纹，同一请求号改变工作表会被拒绝。原有 CSV/TSV/TXT/JSON 请求保持不变。

每行 row 必须唯一。预检返回 ready / duplicate_workspace / duplicate_file / error，可能同时返回容量提示 capacityWarning。提交时仅传选中行，始终保留同一个请求 ID 及内容重试；错误行、非法产品或配额不足不会部分写入。接口不要求上传源文件字节。

解析、真实 SQLite 事务、权限、并发、容量、回滚、回执恢复和前端交互均有自动测试；XLSX 使用 openpyxl 独立生成的合成工作簿验证互操作，以及共享文字/严格格式/CRC/体积/公式错误/切表竞争测试。正式账号的实际文件导入仍需独立验收，浏览器连接不可用时不将其标为已通过。

实现复用已安装的 JSZip 3.10.2 与 saxes 6.0.0。文件结构依据 [Microsoft SpreadsheetML 工作表说明](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-sheets)，流式展开使用 [JSZip internalStream](https://stuk.github.io/jszip/documentation/api_zipobject/internal_stream.html)。
