# 行业题集样本榜单 API

正式登录会话使用 `/api/benchmarks`；外部客户端使用 `/api/v1/benchmarks` 及已授权应用 Key。私有站点的服务访问授权仍需单独满足，不可用执行器凭据代替应用 Key。所有请求显式提供 `brandId`，并受当前工作区、角色与品牌授权限制。

## 创建流程

1. `POST /api/v1/benchmarks/preview`，write 权限。传 `{brandId,spec}`，返回 `{snapshot,snapshotHash,sourceRevision}`，不保存。
2. `POST /api/v1/benchmarks/create`，write 权限。传 `{id,brandId,spec,snapshotHash}`，`spec` 使用预览返回的规范值，`snapshotHash` 使用预览原值，`id` 使用稳定 UUID。同一请求重试返回原快照；同 ID 不同内容返回 409。
3. `GET /api/v1/benchmarks?brandId=...`，read 权限。返回最近 100 份摘要，不返回原文。
4. `GET /api/v1/benchmarks/detail?brandId=...&id=...`，read 权限。返回 `{benchmark,markdown}`，包含固定原始回答、复核和计算结果。没有独立的对外公开链接。

`spec` 字段：

| 字段 | 含义 |
|---|---|
| title | 标题，最多 200 字 |
| industry | 行业，最多 100 字 |
| scope | 所选候选范围及边界，最多 2000 字 |
| method | 题目选择、采样方法及重复方式，最多 2000 字 |
| sourceNote | 实际来源与取得方式，最多 2000 字 |
| surface | `import` 或 `api`，分别统计 |
| metric | `mention` 已复核提及或 `recommendation` 已复核推荐 |
| from / to | UTC 日期 `YYYY-MM-DD`，有序且不晚于今天 |
| minimumAnswers | 每组最少共同回答数，整数 3–1000；不是显著性标准 |
| questionIds | 3–50 个唯一当前品牌问题 ID |
| entityIds | 2–20 个唯一候选 ID：`brand:<品牌ID>`、`competitor:<竞品ID>`；不接受已归档竞品 |

## 分母与计算

同一平台、Web/App/API 入口、模式、地区、语言和已记录模型为一组。模型未记录可形成单独组，但不能证明实际底层模型相同。日期范围和数据类型筛选先于分组。窗口最多 1000 条候选回答。

回答须成功、非演示且有正文，问题 ID、版本、原问题文字与当前所选题目一致。每个候选品牌均需在当前回答与品牌资料下有有效身份复核；推荐指标还需已知推荐复核。未复核与无法判断均使该回答从全部候选品牌分母排除。排除原因保留，不补零。

只有每组达到最少共同样本数、覆盖全部所选题目，`status` 才为 `ranked`。否则为 `insufficient`，`ranking` 为空，返回缺少的题目与原因。

得分为各题正例比例的算术平均。分数以精确整数分子/分母保存和比较，并列使用 1、1、3 竞争排名。`positive/n` 是未加权的原始计数，不能代替每题等权得分。`byQuestion` 保存每题分子分母。显示百分比可能舍入，但不影响实际排名。

## 固定快照与边界

快照含参数、候选身份资料、题目文字/版本、原回答、引用、复核人/时间/原句/编号、分析编号、附件索引、排除记录及计算依据；不复制附件二进制，原件通过有权工作区或完整离线 ZIP 备份取得。附件存在不代表资料已核实。

保存时重新计算快照摘要并核对工作区版本。资料变化返回 409，需重新预览；已成功请求的相同重试会先恢复原回执，即使题目后来移除。历史快照不会随原资料变化。每品牌最多 100 份，快照原文最多 880 KB，超过返回 429 或 413；须缩小窗口/题集，不静默截断。

所有者、管理员、编辑可创建；审核人和只读角色可查看、导出已授权品牌。纳入现有备份恢复与品牌删除。样本范围、来源与采样方式由使用者声明，系统不据此证明行业代表性、授权有效或效果因果关系。测试夹具不上传到生产。
