# 模型配置简化 · 2026-10-15

## 用户路径

简单模式的「模型与账号」只显示连接写作模型所需的内容。助手、开放 API 与回调折叠在开发者接入中。先选择自己已有账号的服务商，再粘贴 API 密钥并保存；随后按需点击一次验证。不配置模型仍可记录消费者回答和创建本地模板。

DeepSeek 预填 deepseek-flash，千问预填 qwen-plus；自定义模型放在折叠区，已保存的模型不会被预设覆盖。千问当前适配中国内地北京 API Key。方舟及 RunningHub 的模型取决于用户账号，保留模型 / 接入点字段，不编造可用型号。

更新现有本地连接时，密钥留空仅更新模型，沿用同一工作区、同一服务商的加密密钥；不会回传密钥、转用他人的密钥或取用服务端托管密钥。首次连接仍须填写自己的密钥。

保存不调用模型；验证是单独的明确动作，最多输出 32 token，并受原预算和调用次数限制。同一验证表单保留请求编号，防止重复提交产生第二次请求。失败提示区分密钥、权限、余额、模型不存在和限流；失败后先引导检查配置，不自动重试。

验证成功只展示简短结果和返回工作台，技术回执折叠保留。DeepSeek Flash / V4 预设使用官方非思考模式，避免小额验证消耗在思考而得不到正文。

## 验收

- 最终代码全量 590 项测试通过。
- 首次浏览器实测已打开简单模式连接页和 DeepSeek 密钥表单，默认仅一个需要填写的密钥输入框，模型名已填并可展开修改。
- 最终构建复测时，侧边浏览器按钮及原生折叠项均无响应，暂无 JS 错误证据；本轮最终点击验收未完成，不能将自动测试替代该项验收。
- 测试覆盖密钥沿用的工作区 / 服务商隔离、格式错误、保留自定义模型、托管配置不复用秘密、验证幂等与 32 token 限制。
- 所有供应商请求在自动测试中使用模拟响应；未使用用户真实密钥或产生真实供应商费用，不能声称某个用户账号已验证成功。
