# 品牌自动运营与稿件生成方案

2026-10-21 · 以当前实现和验收为准。目标是减少客户操作，同时保留事实、费用和公开发送的明确授权。

## 产品判断

个人、产品、企业统一称为品牌。品牌名是入口，不足以直接生成可信宣传：同名消歧、服务范围、真实案例、可公开资料需要来源。首次只填品牌名称和一句介绍，允许从官网或资料导入；集中确认事实一次，后续复用。缺资料时列出具体问题，不用模型补造客户、收入、排名或效果。

建议保留三次必要决定：确认品牌事实、确认本批费用、确认首次公开稿件。整理、去重、任务执行、格式检查、已取得回执的同步自动完成。后续可以设计限定账号、主题、事实库版本和预算的长期授权，但本批不默认开通。

## 当前功能与模型依赖

| 环节 | 当前实现 | 是否依赖模型 |
| --- | --- | --- |
| 建档后初始问题 | 自动生成 5 个可编辑问题，使用本地模板 | 否；不是热度数据 |
| 扩展问题矩阵 | 用户主动选择模型，生成候选并去重，保留原始结果和用量 | 是；候选需选择导入，不证明真实搜索量 |
| 信源汇总 | 从已保存的真实回答和引用统计网页、域名、问题覆盖和日期趋势 | 否；来源分类、相关性和可投稿性仍需核实 |
| 渠道建议 | 基于已核对回答和行业相关性筛选渠道候选 | 规则可完成；没有证据时不生成权威或效果断言 |
| 行动建议 | 根据已有回答、质量检查、资料缺口和回执形成待处理事项 | 规则部分免费；语义判断和模型检查才消耗调用 |
| 一篇稿件 | 免费计划 → 本批费用确认 → 自动写稿 → 自动质检 → 待确认稿 | 写稿、质检各最多 1 次模型请求 |
| 发送结果同步 | 按当前稿件版本读取已返回的 API/连接器回执 | 不调用写作模型；不凭空获取平台未返回的结果 |
| 消费端效果 | 保存真实问题、模式、时间、回答原文和引用，比较同条件样本 | 真实样本不能用普通模型 API 替代；不默认每天付费采集 |

当前客户预览工作区尚未配置真实写作模型，因此没有“实际正在使用的默认大模型”。DeepSeek、通义千问等是可选配置。测试中的“模拟模型-无外部调用”只属于隔离验收环境，不进入客户包，也不代表真实模型质量。

## 自动稿件生成的逻辑

1. 确定当前品牌与问题。优先复用目标需求和已观察问题；模板问题仅作起点，不能当作需求量。
2. 读取该品牌下已确认、未过期、产品范围匹配的资料，保留事实编号、版本、出处。
3. 免费展示内容计划：要回答的问题、依据、建议结构、所选模型、最多调用次数、费用责任。用户改选问题或模型后，旧确认失效。
4. 明确授权后写一篇稿。直接回答具体问题，解释适用条件和方法，真实项目与设计建议分开，缺证据的数字、客户和效果不编造，保留出处和 AI 辅助披露。
5. 同批再检查一次：对照原文和事实，指出缺证据、冲突、遗漏条件；程序独立处理结构和重复度。模型质检是建议，不等于独立核实或批准发布。
6. 保留原稿与检查结果，交用户确认。不默认启动多轮自我改写，避免费用不确定和事实漂移。后续“按问题修改”应先预览修改范围，再单独授权。
7. 勾选自己已核验的账号，按平台真实能力执行草稿或发送。平台格式、封面、分类、声明和身份验证是适配的一部分，不能仅凭登录成功宣布接通。
8. 分别记录已填稿、平台草稿、已提交、审核中、公开可访问。未知结果先核对原任务，不重发。新真实 AI 样本回来后才更新效果；没有新样本显示未知。

本次已实现 1–6 的单篇流程；7–8 取决于已有适配和平台验收，未实现全平台公开提交。完整自动选题运营计划、消费者自动采集、跨平台全部适配仍是后续任务。

## 费用和失败恢复规则

- 查看本批计划、阅读资料、整理已有引用、恢复已取得结果不调用模型。
- 简单流程必须有未预勾的费用确认；授权绑定问题、有效事实、模型及计划摘要。
- 每批只自动执行一次写稿、一次检查。不默认周期采集，不自动开启其他后台任务。
- 供应商限流、预算不足、资料变动、模型变更都会停止；本批不会自动重试或顺延到明日。
- 已保存供应商结果只恢复本地写入；结果不明时先核对供应商。客户明确选择再次付费后才允许重新排队。
- 费用上限首先受工作区预算约束。两次请求不是固定人民币价格；实际 token 和价格由客户供应商计费。本版不显示虚构报价。
- 高级模式原有独立周期任务按各自设置运行，不因这次单篇授权启用；要停止已有周期计划应在任务页暂停。

## 发布实施顺序和完成标准

1. 保留知乎平台草稿的已验收能力，完成头条原稿定位与回执恢复，核验 CSDN/知乎公开提交所需元数据。
2. 对每个平台分别验收账号、正文、图片、平台草稿、提交、公开链接和断线恢复。登录、填入编辑器、自动测试均不能代替公开结果。
3. 处理抖音图文的图片与原稿保护；小红书按用户要求暂停实机验收。
4. 扩展 WordPress、Typecho、MetaWeblog 等接口与后续平台；只有对应动作完成验收才在客户勾选框中开放。
5. 继续简化入口，平台异常尽量在观引“需要处理”统一呈现。当前连接器手动恢复入口为 Chrome 右上角扩展程序 → 观引发布连接器 → 对应平台 → “核对上次回执”。

本轮未自动公开测试文章，未使用第三方收费同步服务，没有承诺 35 个平台已经全部支持自动发布。逐平台状态见《平台能力与验收状态》。
