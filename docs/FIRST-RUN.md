# 第一次使用：一份回答如何变成可核对的报告

这次用构造数据演练“导入回答 → 核对引用 → 导出报告”。不需要模型密钥、登录或 npm 依赖，也不需要上传客户资料。它调用仓库的核心处理函数，不启动桌面 UI；安装包体验见[下载指南](DOWNLOAD.md)。

## 1. 运行

安装 Node.js 24 或更新版本，运行：

```sh
git clone https://github.com/1319974153-ui/guanyin-geo.git
cd guanyin-geo
node examples/first-run/run.mjs
```

程序会打印系统临时输出目录。也可指定一个**不存在**的目录（父目录须存在）：

```sh
node examples/first-run/run.mjs ./first-run-output
```

目录已存在时程序会停止，防止覆盖旧报告；下次使用新目录即可。默认临时输出可能被系统清理，需要留存时自行复制。三个文件均为本机生成，不会自动发布到任何平台。

## 2. 看懂输入

打开 [sample.json](../examples/first-run/sample.json)：

- `text` 是明确标注的虚构练习回答，不是豆包、ChatGPT 等真实结果。
- 问题已更新到 v2，但这条回答采集于 v1，导入后应保留 v1 的题目。
- 两条来源 `https://example.com` 与 `https://example.com/` 指向同一地址，规范化后只保留一条。这里使用占位域名，不会联网读取。
- `dataPurpose: trial` 表示试用演练；不会混入正式效果统计。
- 没有填写已确认的推荐、引用判断，程序应保持待核对。

## 3. 对照输出

| 文件 | 应当看到的结果 | 帮你理解什么 |
|---|---|---|
| `answer.json` | 原文完整、题目为 v1、引用数组只有 1 条 | 原始记录与来源去重 |
| `checks.json` | 7 项检查均为 `true`，外部 AI 请求数为 0 | 不把未知项或演练数据包装成真实结果 |
| `report.md` | 可直接阅读的 Markdown 报告，正式样本为 0 | 演练不会虚增正式统计 |

**为什么不是“推荐率 100%”？** 因为这里没有真实消费者平台回答，也没有人工核实推荐。0 个正式样本是数据隔离生效的预期结果，不能解读为真实产品推荐率为 0。

## 4. 再进入自己的工作区

用[安装包或源码启动](DOWNLOAD.md)后，新建品牌、产品或个人主体，建立问题；实际到消费者平台提问并保存原文、日期、模式和引用，再用回答导入入口登记。真实采集和试用演练分开，未知项不要猜测。报告中的引用仍需打开原来源核对。

本例不是实时 AI 检测，也未验证安装包 UI、外部发布或客户交付。你可以先完成离线演练，再决定是否投入账号接入与真实采集。
