## 当前开发批次

1. 对话写作：允许用一句话调整选题方向，沿用已确认品牌资料；新的方向生成仍先预览调用并确认费用，断网后找回同一结果。

3. 诊断报告：执行步骤可加入关联目标问题、回答依据和筛选范围的待办，重复点击不重复创建。

## 一页产品约定

- 用户：希望品牌或个人 IP 被目标用户和 AI 准确理解的运营者。
- 首次流程：输入名称及可选网址 → 确认匹配身份和可公开资料 → 登录所选渠道 → 一次设置目标、频率、费用上限、自动发布范围。
- 日常流程：自动收集和整理资料 → 发现内容缺口 → 选题与写稿 → 核对事实 → 平台适配 → 按授权发布 → 查询回执 → 复测。首次身份或事实不明时只询问必要信息，不替用户猜测客户、成绩、价格或联系方式。
- 普通界面：运行进度、需要我处理、实际效果。模型、渠道规则和任务细节在高级设置中。平台目录可搜索，不用所有平台图标挤满首次流程。
- 数据属于用户；账号、登录会话、内容、预算按工作区和品牌隔离。同一平台多个账号必须明确选择到账号 ID。
- 本地版独立于 Codex 执行；关机、睡眠和网络中断不承诺继续运行。云托管是另一个后续交付项。
- 模型费用独立：先保留用户自有密钥路径；若普通用户无需配置密钥，需新增有额度和计费边界的托管服务，不能复用作者密钥或把网页登录等同于 API 授权。
- 本轮不自动发布真实社交文章，不修改个人网站，不购买服务，不绕过验证码或既有工具限制，不用演练数据证明收录或推荐。
- 交付顺序：同一源码分支开发和测试 → 隔离预览 → 干净候选包 → Mac/Windows 适用验收 → 正式发行。每阶段单独记录证据。

## 技术实现约束

1. 当前唯一开发目录为 `tmp/guanyin-wechat-20261028`，分支 `codex/wechat-official-publishing`。较早的 `guanyin-product-improve-20261015` 是历史实现目录，不作为本批实现入口。保持既有用户资料与正式版本，交付前验收新构建。
2. `GET /api/publishing-center?brandId=...` 经工作区和品牌权限过滤，返回平台目录、无密钥账号摘要、上次验证状态与当前可执行动作。`batchPublishingAvailable` 按当前可用自建站/API 账号计算；桌面平台仍采用各自已实现、已验收的动作，不将此字段解释为全平台可发布。
3. 复用 `connections` 加密能力，现有 `runs` 和 `publications` 发布记录语义、`wordpress.js` 适配器及后台运行器；不要维护两套相互矛盾的公开回执。新批次只关联渠道运行记录。多账号迁移须单独设计版本字段及备份回退。
4. 计划新增的批次写接口仅在 A03/A04 完成后开放，不能让页面直接调用任意平台 URL。服务端重新校验用户、品牌、账号、连接版本、批准内容及权限，不能信任前端的“已审核”“已连接”标记。
5. 幂等约束包含工作区、品牌、具体账号、稿件/媒体版本和动作；重新打开页面保持原任务编号。业务重复检查独立于客户端请求编号，防止刷新生成新编号导致重发。允许用户有意再发时必须创建明确的新发布意图并提示已有记录。
6. 发布前持久记录发送状态，再执行外部动作；崩溃或超时转入待核对，不能假设失败重发。锁租约到期只允许恢复核对。每个渠道各自失败和恢复。
7. 适配器统一提供能力描述、身份核验、预览/预检、提交、查回执和恢复动作。是否支持草稿/定时/媒体/撤回来自实际适配器；不支持的动作禁用且给出原因。
8. 登录票据只进入用户本地受保护存储或部署方批准的加密存储，不进入稿件、通知、普通日志、导出或安装包。连接更换立即使旧授权快照失效。
9. 截图的全部目标目录详见同批《一键多平台发布需求》。Markdown/PDF 是导出目标；Typecho 和 MetaWeblog 是另行适配的站点/协议；平台访问受限不换路径规避。

## 状态和异常规则

账号：未连接 → 待核验 → 已核验；另有已暂停、权限不足、登录失效。保存的成功核验不等同于当前在线检查，提交时仍要重新检查。

渠道任务：排队 → 预检 → 发送中 → 已提交/平台草稿/审核中/公开待核对 → 已公开；旁支为等待本人操作、可重试失败、结果未知、审核拒绝、已取消。状态转换需要实际响应或查询证据。

平台超时：先查同一个稿件 ID/幂等标记；无法唯一匹配则保留“结果未知”，提供用户核对入口。登录过期：暂停该账号，其他账号继续。材料错误：指出具体缺失项，不调用模型反复付费重写。通知失败：保留站内提醒和真实发送失败记录。

### A03 第一阶段：发布授权快照（2026-11-10）

- 新增 `POST /api/publish-authorizations` 与 `/validate`：只有工作区所有者或管理员在确认已审核稿件后才能创建授权；服务端固定内容哈希、事实快照、具体账号、账号连接版本、动作和 30 秒至 15 分钟的有效期。
- 仅覆盖 WordPress、博客园、Typecho、MetaWeblog、个人官网和语雀等已有服务端账号；浏览器/桌面平台仍使用各自的本机登录、队列和回执保护，不把网页登录状态或目录图标当成服务端发布授权。
- 发送前会自动再次比对稿件正文、事实版本、账号连接版本和本次执行快照；任一变化都会令旧授权失效，不能静默沿用。授权记录不包含账号密钥，也不调用任何平台接口。
- 自动测试覆盖：无外部请求、同一确认的幂等恢复、内容或账号变化失效、角色与品牌隔离，以及页面在真实发送前的调用顺序。全量 `npm test` 构建与测试在本轮通过。
- 第二阶段补齐：确认记录和批次固定图片内容指纹（仅对实际接收该图片的渠道生效）、单次频率、关闭自动重试、模型调用上限 0 与付费同步调用上限 0。更换图片或执行范围不能复用原确认。平台自有账号可能产生的费用仍以平台规则为准，观引不在这一步代扣或估算。
- 这不是平台公开发布验收：授权通过只说明本地发送条件一致；草稿、提交、审核和匿名公开正文仍必须分别以对应平台的真实回执核对。定时调度、后台执行器和未接入渠道的通用图片传递仍未完成。

### A04 第一阶段：持久发布批次（2026-11-10）

- 新增 `POST/GET /api/publish-batches`：发布中心在自建站/API 目标开始发送前，先把已审核稿件、目标账号、账号连接版本、对应授权和稳定任务编号写成一条服务端批次记录。刷新页面或本机重启后可按同一编号读取，不能因为本地 Journal 丢失而生成另一条目标任务。
- 批次创建会再次验证授权、稿件、事实和账号版本；授权过期、改稿、事实变动或账号重连时，不会登记为可发送批次。批次不含密钥、Cookie 或本地文件，也不发起任何平台请求。
- 批次列表只关联已有适配器的稳定任务编号，显示“未开始”、草稿、提交、审核或公开等实际记录；没有远端回执时不把“批次已登记”写成已发布。读取时会重新比较当前已审核稿件与批次内容哈希，改稿后的历史批次不会被恢复到当前稿件。
- 页面将该登记自动放在普通“发布到已选平台”按钮之后，不增加额外确认弹窗；刷新后只显示仍是当前版本的“已登记，待发送”目标。该状态不会轮询平台、不会自动发送，用户重新点击发布后才以新的短期授权开始发送。浏览器/桌面平台继续保留各自的本机登录和任务回执，不混作服务器后台队列。
- 自动测试覆盖批次幂等、回执读取、改稿失效、授权透传和各适配器写入前复核；本轮不启动后台自动发文，也未用真实账号或外部平台验收这项新批次能力。

### A04 第二阶段：单目标发送凭证（2026-11-12）

- 新增 `POST /api/publish-batches/claim`：只有已确认批次中的指定自建站/API 账号，才能在适配器真正写入前领取当前“保存草稿”或“公开提交”步骤。领取动作本身不访问任何平台，也不创建后台任务。
- 同一批次、账号与步骤使用稳定凭证；两个页面同时点击时只有一个可领取。页面收到中断响应后仍可在短时有效期内带同一凭证恢复这一笔明确操作，不会因刷新生成另一条平台请求。
- 凭证过期且没有对应平台运行记录时，批次目标显示“结果待核对”。此时服务端拒绝重新领取，也不会自动补发；操作者先看原平台草稿/提交记录，若确需再发则重新确认一批新的发送操作。
- 发布页把领取安排在只读预览之后、适配器写入之前；保存草稿与公开提交分别领取，保证已有草稿不会被新建稿件覆盖。浏览器/桌面平台仍沿用本机官方窗口的独立回执机制，不将其伪装成服务端后台发送。
- 重开稿件或点击“刷新结果”会读取同一批次的最新状态；旧本地“待发送”状态只会被同一批次的“发送确认中/结果待确认”更新，绝不会覆盖已有平台草稿、提交或公开回执。界面用普通语言说明下一步：先核对原平台，确认未发后才允许再点击发布建立新的明确操作。
- 自动测试覆盖无外部请求、同凭证幂等、并发竞争拒绝、过期转结果待确认、跨页面状态同步、恢复时不自动重发，以及领取发生在真实写入前的顺序。这里仍是本地实现与模拟适配器回归，不等于任何真实账号的公开发布验收。
