# 观引多平台自动运营实施计划

更新：2026-10-19。用户已要求制定方案任务并自主实现。本文件是本轮执行基线；任务状态反映代码、测试和真实验收的不同阶段，不代表正式发行。

## 一页产品约定

- 用户：希望品牌或个人 IP 被目标用户和 AI 准确理解的运营者。
- 首次流程：输入名称及可选网址 → 确认匹配身份和可公开资料 → 登录所选渠道 → 一次设置目标、频率、费用上限、自动发布范围。
- 日常流程：自动收集和整理资料 → 发现内容缺口 → 选题与写稿 → 核对事实 → 平台适配 → 按授权发布 → 查询回执 → 复测。首次身份或事实不明时只询问必要信息，不替用户猜测客户、成绩、价格或联系方式。
- 普通界面：运行进度、需要我处理、实际效果。模型、渠道规则和任务细节在高级设置中。平台目录可搜索，不用所有平台图标挤满首次流程。
- 数据属于用户；账号、登录会话、内容、预算按工作区和品牌隔离。同一平台多个账号必须明确选择到账号 ID。
- 本地版独立于 Codex 执行；关机、睡眠和网络中断不承诺继续运行。云托管是另一个后续交付项。
- 模型费用独立：先保留用户自有密钥路径；若普通用户无需配置密钥，需新增有额度和计费边界的托管服务，不能复用作者密钥或把网页登录等同于 API 授权。
- 本轮不自动发布真实社交文章，不修改个人网站，不购买服务，不绕过验证码或既有工具限制，不用演练数据证明收录或推荐。
- 交付顺序：同一源码分支开发和测试 → 隔离预览 → 干净候选包 → Mac/Windows 适用验收 → 正式发行。每阶段单独记录证据。

3. 复用 `connections` 加密能力，现有 `runs` 和 `publications` 发布记录语义、`wordpress.js` 适配器及后台运行器；不要维护两套相互矛盾的公开回执。新批次只关联渠道运行记录。多账号迁移须单独设计版本字段及备份回退。
4. 计划新增的批次写接口仅在 A03/A04 完成后开放，不能让页面直接调用任意平台 URL。服务端重新校验用户、品牌、账号、连接版本、批准内容及权限，不能信任前端的“已审核”“已连接”标记。
5. 幂等约束包含工作区、品牌、具体账号、稿件/媒体版本和动作；重新打开页面保持原任务编号。业务重复检查独立于客户端请求编号，防止刷新生成新编号导致重发。允许用户有意再发时必须创建明确的新发布意图并提示已有记录。
6. 发布前持久记录发送状态，再执行外部动作；崩溃或超时转入待核对，不能假设失败重发。锁租约到期只允许恢复核对。每个渠道各自失败和恢复。
7. 适配器统一提供能力描述、身份核验、预览/预检、提交、查回执和恢复动作。是否支持草稿/定时/媒体/撤回来自实际适配器；不支持的动作禁用且给出原因。
8. 登录票据只进入用户本地受保护存储或部署方批准的加密存储，不进入稿件、通知、普通日志、导出或安装包。连接更换立即使旧授权快照失效。
9. 截图的全部目标目录详见同批《一键多平台发布需求》。Markdown/PDF 是导出目标；Typecho 和 MetaWeblog 是另行适配的站点/协议；平台访问受限不换路径规避。

## 状态和异常规则

账号：未连接 → 待核验 → 已核验；另有已暂停、权限不足、登录失效。保存的成功核验不等同于当前在线检查，提交时仍要重新检查。

渠道任务：排队 → 预检 → 发送中 → 已提交/平台草稿/审核中/公开待核对 → 已公开；旁支为等待本人操作、可重试失败、结果未知、审核拒绝、已取消。状态转换需要实际响应或查询证据。

平台超时：先查同一个稿件 ID/幂等标记；无法唯一匹配则保留“结果未知”，提供用户核对入口。登录过期：暂停该账号，其他账号继续。材料错误：指出具体缺失项，不调用模型反复付费重写。通知失败：保留站内提醒和真实发送失败记录。

## 统一测试矩阵

- 权限：用户 A/B、品牌 A/B、同平台多个账号、管理员/编辑/只读角色；跨域读写、密钥泄漏和断开连接后的残留任务。
- 正确性：未审核不能发；审核后稿件、事实、媒体或账号变化使批准失效；各平台排版和来源声明一致。
- 重复：双击、两个浏览器并发、服务重启、外部成功后响应丢失、先超时后迟到响应；同一内容不能悄悄创建第二篇。
- 故障：断网、登录过期、平台限流、权限不足、远端修改、审核拒绝、回执不存在/多条；只恢复对应渠道。
- 调度：Asia/Shanghai 显示、UTC 存储、日期边界、睡眠恢复、错过时段、每日上限、暂停/取消与发送竞态。
- 交付：空配置、中文及空格路径、无 Node 环境、双实例隔离、数据重启保留、退出/卸载说明、Mac/Windows 各自验收。
